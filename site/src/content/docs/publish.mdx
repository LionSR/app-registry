import { Steps, TabItem, Tabs } from '@astrojs/starlight/components';

Publishing takes two steps. First, the APP plugin helps you turn the folder with your paper into a GitHub release that any coding agent can open. That release is your publication, and it stays in your own repository. Then you submit it here, so readers can find it.

These instructions follow the [APP protocol's README](https://github.com/LionSR/AgenticPublicationProtocol#install-and-update), which also explains how to update the plugin and how to install it by hand.

## 1. Publish

<Steps>

1. Install Claude Code or Codex, then add the APP plugin to it. APP runs inside the agent; it is not a separate program.

   <Tabs syncKey="agent">
   <TabItem label="Claude Code">

   Type these at the Claude Code prompt, inside a running session (start one with `claude`), not in your shell:

   ```text
   /plugin marketplace add LionSR/AgenticPublicationProtocol
   /plugin install paper-protocol@paper-protocol
   /reload-plugins
   ```

   </TabItem>
   <TabItem label="Codex app">

   1. Open **Plugins** and click **Add → Add marketplace**.
   2. Enter `LionSR/AgenticPublicationProtocol` as the source, leave Git ref and Sparse paths empty, and click **Add marketplace**.
   3. Search the plugin list for `paper-protocol` and switch it on.

   </TabItem>
   <TabItem label="Codex in a terminal">

   Run these in your shell, not inside Codex:

   ```bash
   codex plugin marketplace add LionSR/AgenticPublicationProtocol
   codex plugin add paper-protocol@paper-protocol
   ```

   </TabItem>
   </Tabs>

2. Open the folder with your paper, code and data in the agent, and start publishing.

   <Tabs syncKey="agent">
   <TabItem label="Claude Code">

   ```text
   /publish-paper
   ```

   </TabItem>
   <TabItem label="Codex app">

   ```text
   $publish-paper
   ```

   </TabItem>
   <TabItem label="Codex in a terminal">

   ```text
   $publish-paper
   ```

   </TabItem>
   </Tabs>

   The agent guides you step by step: it checks your results, tidies the repository, writes the paper's agent instructions with you, and makes the release. It asks before each important step, and you can stop and continue later. If you let it use your GitHub account, it makes the release for you; otherwise it tells you what to run.

</Steps>

When it is done, your repository has a new GitHub release. That release is your publication, whether or not it is listed here. [More on publishing](../guides/publish/).

## 2. Submit it here

[Submit your release](../submit/): sign in with GitHub and choose the release. We check it, and your paper usually appears on this site right away; sometimes an editor takes a look first. Submitting does not change your repository.
