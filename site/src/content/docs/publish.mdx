import { Steps, TabItem, Tabs } from '@astrojs/starlight/components';

A paper reaches this site in two steps. First you **publish** it: the APP skills turn your working folder into a GitHub release that any coding agent can open. That release is the publication, and it stays in your own repository. Then you **submit** the release to the registry, so readers can find it here.

These instructions follow the [APP protocol repository's README](https://github.com/LionSR/AgenticPublicationProtocol#install-and-update), which also covers updating and manual installation.

## 1. Publish

<Steps>

1. Install Claude Code or Codex, then add the APP plugin to it. APP runs inside the agent; it is not a separate program.

   <Tabs syncKey="agent">
   <TabItem label="Claude Code">

   Type these at the Claude Code prompt, inside a running session (start one with `claude`), not in your shell:

   ```text
   /plugin marketplace add LionSR/AgenticPublicationProtocol
   /plugin install paper-protocol@paper-protocol
   /reload-plugins
   ```

   </TabItem>
   <TabItem label="Codex app">

   1. Open **Plugins** and click **Add → Add marketplace**.
   2. Enter `LionSR/AgenticPublicationProtocol` as the source, leave Git ref and Sparse paths empty, and click **Add marketplace**.
   3. Search the plugin list for `paper-protocol` and switch it on.

   </TabItem>
   <TabItem label="Codex in a terminal">

   Run these in your shell, not inside Codex:

   ```bash
   codex plugin marketplace add LionSR/AgenticPublicationProtocol
   codex plugin add paper-protocol@paper-protocol
   ```

   </TabItem>
   </Tabs>

2. Open the folder that holds your paper, code and data in the agent, and start the publishing workflow.

   <Tabs syncKey="agent">
   <TabItem label="Claude Code">

   ```text
   /publish-paper
   ```

   </TabItem>
   <TabItem label="Codex app">

   ```text
   $publish-paper
   ```

   </TabItem>
   <TabItem label="Codex in a terminal">

   ```text
   $publish-paper
   ```

   </TabItem>
   </Tabs>

   The workflow reproduces or checks your results, organizes the repository, drafts `AGENTS.md` with you, validates everything, and creates the GitHub release. It asks for your approval at each checkpoint and can span several sessions. To let the agent create the release itself, it needs access to your GitHub account; otherwise it tells you which commands to run.

</Steps>

The result is a GitHub release of your repository with an `APP_PUBLICATION.json` file attached. That release is a complete APP publication, whether or not it is listed here. [More on publishing](../guides/publish/).

## 2. Submit to the registry

[Submit your release](../submit/) by choosing its repository and tag. The registry checks the release, an editor approves it, and the paper then appears on this site with a registry ID such as `APP-260923-0000`. Submitting does not change your repository.
