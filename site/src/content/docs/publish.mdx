Publishing includes two steps:
1. Create a validated GitHub release in your repository with the APP plugin.
2. Submit the release to this registry so readers can find your paper.

You can also instruct your AI coding agent to complete these steps: tell the agent to *publish my paper following agenticpapers.app*. The agent reads the [agent instructions](../start.md), requests permission to install the plugin, and starts the workflow.

These instructions align with the [APP protocol specification](https://github.com/LionSR/AgenticPublicationProtocol#install-and-update).

## 1. Publish

<Steps>

1. Install Claude Code or Codex, then install the APP plugin. The plugin runs directly inside the AI agent.

   <Tabs syncKey="agent">
   <TabItem label="Claude Code">

   Enter these commands in the Claude Code prompt during an active session (type `claude` in your terminal to start):

   ```text
   /plugin marketplace add LionSR/AgenticPublicationProtocol
   /plugin install paper-protocol@paper-protocol
   /reload-plugins
   ```

   </TabItem>
   <TabItem label="Codex app">

   1. Open **Plugins** and select **Add → Add marketplace**.
   2. Enter `LionSR/AgenticPublicationProtocol` as the source. Leave Git ref and Sparse paths empty. Select **Add marketplace**.
   3. Locate `paper-protocol` in the plugin list and enable it.

   </TabItem>
   <TabItem label="Codex in a terminal">

   Run these commands in your shell:

   ```bash
   codex plugin marketplace add LionSR/AgenticPublicationProtocol
   codex plugin add paper-protocol@paper-protocol
   ```

   </TabItem>
   </Tabs>

2. Open the directory containing your paper, code, and data in the agent, then start publishing.

   <Tabs syncKey="agent">
   <TabItem label="Claude Code">

   ```text
   /publish-paper
   ```

   </TabItem>
   <TabItem label="Codex app">

   ```text
   $publish-paper
   ```

   </TabItem>
   <TabItem label="Codex in a terminal">

   ```text
   $publish-paper
   ```

   </TabItem>
   </Tabs>

   The agent guides you through the workflow. It verifies your results, organizes files, drafts `AGENTS.md`, and creates the release. The agent requests confirmation before each critical operation. You can pause the workflow and resume later. If you grant GitHub access, the agent creates the release automatically. Otherwise, the agent outputs the required Git commands.

</Steps>

When the workflow finishes, your repository contains a new GitHub release. This release is your published paper. For detailed information, see the [publishing guide](../guides/publish/).

## 2. Submit to the registry

[Submit your release](../submit/) to the registry: sign in with GitHub and select the release. The registry verifies the release automatically. If checks pass, your paper appears in the registry immediately. If checks flag items, an editor reviews the submission. Submitting does not modify your repository.
