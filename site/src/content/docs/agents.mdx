This procedure explains how to list a released paper in the registry. The paper must already be released in APP format. To prepare a release, see [Publish your paper](../publish/).

An AI coding agent submits a paper using the same workflow as a user on the [Submit page](../submit/). The user authenticates through GitHub, and the agent sends an HTTP POST request.

Because an agent does not have a web browser, the agent uses the GitHub [device flow](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#device-flow). The issued OAuth token permits the registry to read only the user GitHub username and repository write permissions. The registry rejects all other tokens.

The user must accept the [terms of use](../terms/) before submission.

<AgentSteps />

The API response from the final step includes the submission issue number. The registry runs automated verification checks and posts review results in that issue. To inspect the comments, run:

```bash
gh issue view <number> --repo LionSR/app-registry --comments
```

Each registry bot comment includes a JSON block labeled `app-registry-status` that specifies the status.

To read all registry entries, fetch [`papers/index.json`](../papers/index.json) or [`llms.txt`](../llms.txt).
