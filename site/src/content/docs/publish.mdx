Getting your paper onto this site takes two separate steps.

|  | 1. Publish | 2. Submit to the registry |
|---|---|---|
| What you get | An APP publication: a tagged GitHub release of your paper repository that any agent can open | A listing on this site with a permanent ID such as `APP-260923-0000` |
| Where it lives | Your own GitHub repository | This registry |
| How | Run the `publish-paper` skill in your coding agent | [Submit](/submit/) the link to your release |
| Required? | Yes. This is the publication. | No. It makes your paper easy to find. |

Publishing never depends on the registry. Your release is a complete APP publication whether or not it is listed here, and listing it does not change your repository.

## 1. Publish

Turn a finished paper into an APP publication in your own GitHub repository. Nothing is released without your approval.

<Steps>

1. Install the APP plugin in your coding agent.

   <Tabs syncKey="agent">
   <TabItem label="Claude Code">

   ```text
   /plugin marketplace add LionSR/AgenticPublicationProtocol
   /plugin install paper-protocol@paper-protocol
   /reload-plugins
   ```

   </TabItem>
   <TabItem label="Codex">

   ```bash
   codex plugin marketplace add LionSR/AgenticPublicationProtocol
   codex plugin add paper-protocol@paper-protocol
   ```

   </TabItem>
   </Tabs>

2. Open the folder with your paper, code and data, and run the publishing skill. It walks you through reproducing results, organizing the repository, writing `AGENTS.md`, validating, and releasing.

   <Tabs syncKey="agent">
   <TabItem label="Claude Code">

   ```text
   /publish-paper
   ```

   </TabItem>
   <TabItem label="Codex">

   ```text
   $publish-paper
   ```

   </TabItem>
   </Tabs>

</Steps>

When the skill finishes, your repository has a GitHub release with an `APP_PUBLICATION.json` file attached. That release is your publication. [Read the full publishing guide](/guides/publish/).

## 2. Submit to the registry

[Submit your release](/submit/) with its GitHub link. The registry checks that it is a verified APP publication, and an editor lists it here with a permanent ID. You can follow and reply to the review on GitHub.
